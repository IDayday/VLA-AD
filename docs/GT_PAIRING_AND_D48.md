# GT 配对与 D48 教师的关系

正式教师使用完整原 GT 配对流程。GT 配对、子空间拟合、专家拟合和全量教师生成各自完成不同工作。

GT 配对时，Base 模型参数被冻结；接口修复变量 `delta` 是 `torch.nn.Parameter`。原动作网络和五步去噪链仍建立输入梯度，预测轨迹与 GT 计算可微损失，执行 `loss.backward()` 和 Adam 更新。标准目标为缩放 XY 的 Smooth L1 加航向余弦误差，专门阶段使用原配置的目标变体。模型冻结检查同时核对 requires_grad、参数grad和参数版本；冻结模型不等于切断接口梯度。

每个原配置完成其规定步数。记录迭代候选后，独立计算真实 S0 PDMS 选择修复；S1/S2只检查迁移，不反向参与选优。Base保留和并列规则沿用原实现。最终完整接口、mask、轨迹、评分和SHA来自实际执行。

D48根据本机成功修复与冻结Base的差分拟合；不是只对Base表征降维后就获得教师。先在完整384维差分方向空间聚为K8，各簇专家使用共享48维坐标拟合，完成校准、全Train侧重拟合和增强后冻结。全量Train/Test再用五组噪声评测Base+8分支并固定场景选择。

已有配对矩阵的秩与簇支持检查只证明技术上能拟合；它们不能证明提前结束搜索不会降低教师效果。因此正式流程继续全部原定配对阶段。曾建立的短版cut仅为保留的工程探索，未作为正式教师输入。

当前分片粒度为一个原优化配置。独立进程通过文件锁领取工作，已完成结果复用；同卡多进程不会合并不同场景梯度或更改采样器、步数、幅度与评分规则。额外并发应按每张物理GPU的实际完成吞吐选择，不能把多个进程墙钟之和当作加速倍数。
