# 本机 D_C8_double 教师与 Round1 执行协议

本次只重建“差分、先聚类、K8、增强”这一套理想修复教师。最终参数、子空间、场景选择和教师目标均来自本机实际计算；原 PPU 数值仅用于追溯方法。学生实验使用这套新教师，原九组暂停实验保持暂停。

## D / C_to_P / K8 / double 的具体含义

`fitting/PLAN.json` 固定原数学源码、函数绑定、样本与配置身份。

1. 在本机成功的 Base/GT-post 配对上，按原定义构造有效 token 的共享 384 维差分。
2. 重拟合共享 D48。D 路径解码差分，不给学生添加中心偏置。
3. 按原 `C_to_P` 顺序，在完整 384 维方向空间先聚为 8 簇，再在共享子空间拟合各簇的候选算子。
4. 单库内部保留原 13 种候选算子：mean、contract、boundary、ot、local、linear、linear_replay、mlp、mlp_replay、paired_RRR、direction_amplitude、soft_clip、centroid_D0。两种 MLP 均按原配置训练 2,000 次更新。这些候选是 D_C8 构建过程的一部分。
5. 候选剂量为 `(alpha, cap/D0)`：`(0.25,2)`、`(0.5,2)`、`(0.75,2)`、`(1,2)`、`(1.5,2)`、`(2,2)`、`(0.5,1)`。
6. 原 32 场景 pilot 用 S0/S1，原 2,021 场景校准用 S0/S1/S2。沿用原自然人口权重、粗筛、两起点坐标选择、并列规则及最终全 Train 侧重拟合/簇匹配。
7. 增强在最终库上对原始修复量和幅度上限同时乘 2；不改变优化器、采样器或另行探索其它教师库。
8. 冻结之后，完整 Train/Test/Validation 分别实测 Base+8 个分支，每场景根据 S0–S4 平均真实 PDMS 选同一分支。先转 FP64 PDMS 点数再做 argmax，精确并列优先 Base。五次噪声共用该选择。

最终教师不设置“低于 70 才修复”等部署筛选。前述失败配对资格只用于原教师拟合阶段。完整候选选择是离线 Oracle 上限，不能称为单次前向学生成绩。

## 本机数值路径与监督数据

沿用本机已验收的 Native 路径：Torch 2.5.1/cuDNN 90100、transformers 4.37、原 VLM BF16、投影和动作头 FP32，关闭 TF32/autocast。完整 token 布局及 padding 原值保留。严格 PPU 逐位对齐不属于本轮目标。

CPU 数学派发同样固定：`OPENBLAS_CORETYPE=Sandybridge`，BLAS/OMP 线程为 1。一次未设置 CORETYPE 的独立诊断未通过历史 FP64 请求字节检查；恢复上述设置后，原包 388 个文件哈希、24 组真实参考及 188 个专家请求检查均通过。这项检查用于环境和资产验收，不把历史教师参数用于新实验。

动作链复用原 get_action 的五步 DDIM `[80,60,40,20,0]`、eta=1、随机模式、逐步噪声 clip ±1、std floor=1e-4，末步也保留最小噪声。优先使用已保存并校验的完整六次随机抽样带，不用相同 seed 代替显式噪声。

Train/Val/Test 原生 post384 已各自保存为完整 FP32 mmap。完整教师评分保存实际执行的轨迹、七项评分、actual_role_shifts、实际 RMS/上限、mask、token 与噪声身份，并引用不可变 Base mmap 及其字节哈希。读取时按实际 shift 重建完整教师接口并逐值核对；不重复存储大体积 Base，也不混合旧平台轨迹与本机接口。

新学生只读普通 post384 和 24 维状态，不读专家标签或离线收益。full/gain1 的收益阈值仅在冻结目标构造中使用。Train-only 目标清单保持不可变；Validation/Test 诊断目标使用各自独立清单。

## 验收与执行状态的含义

- 源码、输入、采样链、独立评分和数学算子检查通过，仅表示对应工程检查通过。
- 已完成的真实 64 场景已知可实现正控制及四卡尾批检查，不代表正式蒸馏完成。
- 推理 CUDA 图只减少启动开销。第一版工程实现复用了调用者张量作为图的静态输入，重放会改写首场景输入；只对输出的早期检查因此无效，相关验收已经作废并留档。修复后所有静态输入独立 clone；两台机器各 48 个真实场景的输出、调用者输入及保留的中间状态均逐字节通过，旧实现的新增负控制如期失败。Base 缓存与 GT 优化不使用此工程推理图，未受该问题影响。需要梯度的查询继续调用原生路径。
- C 组使用纯内存的冻结教师前缀缓存，复用同场景、同训练 seed/噪声带已经计算的状态和均值；较长查询只扩展尚未计算的前缀。在修复后的推理图上重新完成 64 个真实场景 × 两个训练 seed × 五个噪声带的 640 组条件，已逐字节核对五个时间步的冷启动、命中、反向访问和淘汰后重算，并确认末步噪声、RNG 与冻结参数保持一致。D 组持续按当前学生表征生成状态；学生均值查询始终保留原生 autograd。
- 功能损失开启后的恢复须单独通过真实反向检查。注意力反向的微小非确定性不能用放宽比较误差来掩盖；冻结网络的前向输出也必须重新核验。
- 本机已用 64 个真实场景、五个时间步核验：仅在需要梯度的学生均值查询及反向阶段启用确定性元数据，前向均值与原生路径逐位一致，C/D 的已更新 Adam 独立恢复也完全一致。PyTorch 原生注意力反向会读取该确定性标志，参见 [v2.5.1 官方实现](https://github.com/pytorch/pytorch/blob/v2.5.1/aten/src/ATen/native/transformers/cuda/attention_backward.cu)。原生 teacher/state/get_action 前向保留原设置；该范围也满足 AOTAutograd 的前反向标志约束。
- 正式结果必须由实际完成的场景、更新数、退出状态和文件 SHA 证明。排队、后台启动、loss 下降均不等于完成。

教师生成的持久控制器为 `code/local_teacher_suite.py`；新学生准备与完整实验控制器为 `code/round1_prepare_and_run.py`。它们等待真实产物与真实子进程退出，支持检查已完成阶段后继续。第一轮八个学生任务均完成 40 epochs，并完成规定验证、锁定权重后测试、诊断与最终报告，才进入 REPORT_COMPLETE。

训练集超过 97、测试集超过 96 是研究目标。当前新教师未评分前，不承诺或填入这些分数；结果不达目标时保留负结果，不依据 Test 反复调参。
